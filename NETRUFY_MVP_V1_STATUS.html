Discover people, skills, and services in a real community. See which community relationships have been confirmed. Connect directly, while members control what they share.

01 · Executive summary

Where the product stands

Netrufy is a community directory and membership network, not yet a general job board or marketplace. The first release focuses on people and services that belong to an existing community.

Launch status: the Angular application builds, but the latest database migration and Edge Functions must be applied/deployed to the existing Supabase project, and the live email/SMS/storage flow must be tested before inviting a pilot group.

The sample directory records were removed when search switched to real Supabase data. Public search intentionally shows only profiles that opt in. Existing members default to hidden until they enable public listing and choose which fields are public.

02 · Product structure

How Netrufy is organized

Community

The tenant boundary. Members and groups belong to a community.

Unit

The department/group used for member applications and Unit-leader review.

Homecell

A separate fellowship affiliation and additional community verification signal.

Member

A Supabase Auth account with a Netrufy profile, optional affiliations, skills, services, and chosen visibility.

Unit and Homecell are parallel community relationships. A confirmed membership proves connection to that group, not professional certification or service quality.

04 · Trust and guarantors

What “vouching” proves—and what it doesn’t

The previous guarantor request accepted any phone number. That meant a user could nominate someone outside the platform; the SMS OTP proved control of that phone, not community eligibility. This was a real trust gap.

Current code change: the request now requires the phone to match a Netrufy profile in the same community with at least one verified Unit/Homecell membership. The displayed name is taken from that profile. SMS OTP, a single-use link, expiry, attempt limits, and audit logging remain part of the flow.

Remaining distinction: this allows any verified group member to vouch, not only a leader. Phone verification confirms access to a registered number; it does not independently prove identity, closeness of relationship, professional skill, or future conduct. If the product promise requires official endorsement, restrict guarantors to designated leaders or admins. Otherwise label the signal “member confirmed” and keep “vouch” as an attributed personal statement.

SMS delivery requires the request-attestation, guarantor-send-otp, guarantor-status, and guarantor-submit functions plus Termii credentials and APP_URL. The flow has not been verified against the live SMS provider.

05 · Architecture and safeguards

What protects the data

  • Supabase Auth stores passwords; Netrufy does not store raw passwords in its profile table.
  • Postgres RLS separates communities and permits Unit leaders to review only their Unit's application queue.
  • The public directory uses a dedicated safe view; it does not expose phone numbers or private fields.
  • Application photos live in a private bucket until review. Approved opted-in photos are copied to public profile storage.
  • Public listing and per-field audiences are separate controls; public listing is off by default.
  • Edge Functions use the service role only server-side for privileged application, invitation, and guarantor actions.
Operational caveat: deleting/withdrawing public consent must also remove or privatize an already-published photo object; otherwise a previously copied public URL could remain accessible. Verify this revocation path before a broad launch.

06 · Launch blockers

Do these before a real pilot

  1. Apply migration 0005 once to the existing Supabase project if it has not already succeeded. It adds applications, public views, profile listing/photo fields, invite bindings, and storage policies.
  2. Deploy all Edge Functions, especially submit-membership-application, review-membership-application, updated redeem-invite, and all four guarantor functions.
  3. Configure URLs and secrets: Auth callback allow-list, APP_BASE_URL, APP_URL, Termii API key and approved sender ID, plus deployed app URL.
  4. Assign Unit leaders and verify each leader has an active verified membership in the Unit they manage.
  5. Complete a real pilot walkthrough: public search → application → compressed photo upload → leader notification/review → rejection and approval → email-bound signup → profile creation → public consent → contact reveal → guarantor request.
  6. Test privacy and abuse boundaries: anonymous access, wrong-community leader, wrong invite email, duplicate application, oversized/wrong-type photo, expired invite, removed membership, SMS failure, and public-photo revocation.

The Angular development build passes. Supabase SQL, Edge Functions, RLS, Storage, realtime notifications, and Termii have not been exercised end-to-end from this environment.

08 · Recommended MVP v1

Keep the launch focused

Visitor

Land on search, search public profiles without an account, view only consented information, apply to a Unit.

Applicant

Submit a small photo and details; wait for Unit review; receive a bound signup invitation if approved.

Unit leader

Review applications, approve/reject with a reason, maintain the roster, and see who is responsible for the Unit.

Member

Set up a password, edit profile, choose public fields, publish profile if desired, and connect through disclosed channels.

Launch order

  1. Complete Supabase migration/deploy/configuration and assign leaders.
  2. Run one Unit with 20–50 invited/applicant members and verify photo/privacy/moderation operations.
  3. Measure searches, profile opens, contact requests, approved applications, and successful connections.
  4. Only then add notification email, businesses, opportunities, or messaging based on pilot feedback.
Core principle

Netrufy makes relevant community relationships visible. It facilitates trust; it does not certify professional ability or guarantee outcomes.
